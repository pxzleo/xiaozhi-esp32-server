# 网易云音乐滚动歌词客户端修改契约

## 目标与边界

客户端在网易云音乐播放期间固定显示三行歌词：上一行、当前行、下一行。服务端负责获取和解析 LRC 时间轴，客户端负责歌词页面、播放时钟、三行窗口计算和渲染。

歌词进度必须由客户端实际播放的 PCM 样本数驱动，不能使用服务端发包时间、消息接收时间、Opus 包数量或普通墙上时钟估算。客户端不需要高频向服务端上报播放进度。

## 传输协议

沿用设备 WebSocket 的 MCP 单向通知：

```json
{
  "type": "mcp",
  "payload": {
    "jsonrpc": "2.0",
    "method": "notifications/netease_music/lyrics",
    "params": {}
  }
}
```

未知版本或未知 `action` 必须忽略，不得断开设备连接。

### 开始事件

服务端保证 `start` 通知在对应歌曲的第一个音乐 Opus 帧之前写入同一流控队列；登录提示或“正在播放”语音位于该通知之前。

```json
{
  "version": 1,
  "action": "start",
  "playback_id": "32位十六进制随机标识",
  "track": {
    "id": "33894312",
    "title": "歌曲名",
    "artists": ["歌手一", "歌手二"]
  },
  "available": true,
  "lines": [
    {"start_ms": 1200, "text": "第一句"},
    {"start_ms": 5450, "text": "第二句"}
  ]
}
```

字段约束：

- `version` 当前固定为 `1`。
- `playback_id` 每次开始、继续、上一首、下一首或跳转都会更新，用于隔离旧播放状态。
- `track.id` 是十进制字符串。
- `lines` 按 `start_ms` 升序排列，最多 500 行；单行最多 200 个字符，全部歌词最多 32000 个字符。
- `available=false` 时 `lines=[]`，客户端显示歌曲信息和“暂无歌词”，但音乐继续播放。

### 清除事件

```json
{
  "version": 1,
  "action": "clear",
  "reason": "paused"
}
```

`reason` 可能为 `paused`、`stopped`、`interrupted`、`completed` 或 `closed`。收到后必须立即停止歌词时钟、释放时间轴并退出歌词页；重复清除必须幂等。

## 客户端播放时钟

1. 收到 `start` 后保存时间轴和 `playback_id`，进入等待首个音乐帧状态，不立即启动计时。
2. 同一 WebSocket 上，`start` 后的首个二进制音频帧属于该歌曲；解码并接受该帧时将歌词位置重置为 0。
3. 每次 PCM 被音频输出设备实际消费后累计 `rendered_samples`：`position_ms = rendered_samples * 1000 / sample_rate`。
4. 网络预缓冲、解码队列或扬声器尚未消费的 PCM 不计入播放进度。
5. 当前“继续播放”会从歌曲开头重新播放并下发新的 `playback_id`，不得沿用暂停前的歌词位置。
6. 新 `start` 自动替换旧播放状态，旧音频回调和旧界面刷新任务必须失效。

如果音频驱动只能提供已写入 DMA 的样本数，应减去尚未消费的 DMA/扬声器缓冲样本，歌词同步误差目标不超过 150 ms。

## 三行窗口算法

1. 使用二分查找找到最大的 `i`，满足 `lines[i].start_ms <= position_ms`。
2. `i` 不存在时，上一行和当前行为空，下一行显示首行。
3. `i` 存在时，依次显示 `lines[i-1]`、`lines[i]`、`lines[i+1]`，越界位置为空。
4. 相同时间戳的多行保持服务端顺序，当前行取该时间戳的最后一行。
5. 每 50～100 ms 检查一次位置，仅在当前行索引变化时重绘歌词文本。

## 页面、资源与安全要求

- 页面固定显示歌曲名、歌手名和三行歌词；当前行突出，前后行弱化。
- 文本过长时单行省略或裁切，不得改变三行布局高度。
- `available=false` 时当前行显示“暂无歌词”，其他两行为空。
- 歌词页不得覆盖登录二维码页；暂停、停止、打断或队列结束时恢复设备原页面。
- 时间轴仅保存在 RAM，不写入 NVS、日志或崩溃转储。
- 不记录完整歌词正文；日志只允许记录 `playback_id`、歌曲 ID、行数和状态。
- 字段缺失、类型错误、负时间戳或数组未排序时拒绝本次歌词事件，但音乐必须继续播放。

## 客户端验收用例

1. 开场语音期间歌词时钟保持 0，首个音乐 PCM 实际播放后才推进。
2. 每个时间戳前后 100 ms 的上一行、当前行、下一行均正确。
3. 人为增加 2 秒网络预缓冲，歌词仍与扬声器实际声音同步。
4. 下一首、上一首和跳到第 N 首后，旧 `playback_id` 不再更新界面。
5. 暂停、停止、语音打断和队列自然结束均退出歌词页。
6. 无歌词、500 行边界、超长单行和错误 JSON 不影响音乐播放。
7. 不支持本通知的旧客户端继续正常播放音乐。
